## 一、对话链路流程

<a id="arch-overview"></a>

### 1.1 系统架构总览

灵犀系统采用 **Java + Python 双服务架构**，Java 负责业务逻辑和数据持久化，Python 负责 AI 模型调用和 Prompt 构建。两者通过 HTTP/SSE 协议通信，使用共享密钥 `X-Agent-Service-Key` 进行服务间认证。

**Java 服务（lingXi-manage）** 负责：
- 用户身份鉴权与会话归属校验
- 对话历史持久化（MySQL）
- 看板数据加载与组装
- 会话 CRUD 管理
- SSE 事件转发给前端
- 共享密钥认证

**Python 服务（lingXi-agent）** 负责：
- LLM 模型调用（通义千问等）
- Prompt 动态构建与组装
- 工具执行（Tavily 联网搜索）
- 结构化输出解析
- 短期记忆管理（PostgreSQL/InMemory）
- SSE 事件生成

### 1.2 普通对话流程（同步）

#### 入口接口

`POST /api/ai/chat` - 发送消息到大模型并返回回复

#### 调用链路

```
前端
  ↓ POST /api/ai/chat (sessionId + message)
AiController.chat()
  ↓ 获取当前用户 ID
  ↓ requireOwnedSession(sessionId, userId) 校验会话归属权
QwenServiceImpl.chat()
  ↓ requireValidSessionId(sessionId) 校验会话 ID 格式
  ↓ requireValidText(message, "消息") 校验消息非空且不超长
  ↓ saveUserMessage() 持久化用户消息到 DB
AgentClient.chat(message, sessionId, userId)
  ↓ 构建请求体 JSON
  ↓ HTTP POST → Python Agent /api/v1/chat/invoke
Python Agent 接收请求
  ↓ require_service_auth() 校验 X-Agent-Service-Key
  ↓ create_agent_context() 构建 AgentContext(user_id, thread_id, style, business_tag)
  ↓ get_agent() 获取/缓存编译后的 Agent 图
  ↓ agent.ainvoke() 执行 LLM 调用（可能包含工具调用如搜索）
  ↓ 返回最终回复文本
QwenServiceImpl
  ↓ saveAssistantReply() 持久化助手回复到 DB
AiController
  ↓ 返回文本回复给前端
```

### 1.3 流式对话流程（SSE）

#### 入口接口

`POST /api/ai/chat/stream` - 流式发送消息到大模型并返回 SSE 流

#### 调用链路

```
前端
  ↓ POST /api/ai/chat/stream (sessionId + message)
AiController.streamChat()
  ↓ requireOwnedSession() 校验会话归属权
QwenServiceImpl.streamChat()
  ↓ 校验会话 ID + 消息
  ↓ saveUserMessage() 持久化用户消息
  ↓ 创建 SseEmitter（超时 310s）
  ↓ 注册 completedReplyConsumer（流结束后一次性保存助手回复）
AgentClient.streamChat()
  ↓ 提交 streamTask 到线程池（核心4/最大16线程）
  ↓ HTTP 连接 Python Agent /api/v1/chat/stream
Python Agent 接收请求
  ↓ require_service_auth() 校验密钥
  ↓ create_agent_context() + get_agent()
  ↓ agent.astream() 流式执行 LLM
  ↓ 逐块生成 SSE 事件:
      - token:        文本增量（逐 token 推送）
      - tool_start:   工具调用开始（工具名 + 输入参数）
      - tool_end:     工具调用结束（工具名 + 输出结果）
      - custom:       自定义进度事件
      - heartbeat:    心跳保活（每 15s 发送一次，防止连接超时）
      - done:         流结束（携带完整回复文本）
      - error:        错误事件
Java AgentClient 读取 SSE 行
  ↓ 逐行解析 "data: {...}" 事件
  ↓ 转发 token 事件给前端 (emitter.send)
  ↓ 拼接完整回复 fullReply
流结束后
  ↓ completedReplyConsumer → saveStreamReplyOnce() 持久化完整回复（AtomicBoolean 防重复）
  ↓ emitter.complete()
前端接收 SSE 事件流，实时渲染回复
```

#### SSE 事件格式

```json
// 文本增量
data: {"type":"token","content":"这是","request_id":"xxx","thread_id":"xxx"}

// 工具调用开始
data: {"type":"tool_start","tool":"web_search","tool_input":{"query":"搜索词"}}

// 工具调用结束
data: {"type":"tool_end","tool":"web_search","tool_output":"搜索结果..."}

// 心跳保活
data: {"type":"heartbeat"}

// 流结束
data: {"type":"done","content":null}

// 错误
data: {"type":"error","content":"Agent stream failed"}
```

#### 关键文件

| 层级 | 文件 | 职责 |
|------|------|------|
| Java SSE 处理 | [AgentClient.java](../dkd-parent/lingXi-manage/src/main/java/com/lingXi/ai/client/AgentClient.java) | 流式 HTTP 连接、SSE 解析、转发 |
| Python 流式端点 | [app/api/v1/chat.py](../lingXi-agent/app/api/v1/chat.py) | SSE 事件生成、心跳保活、断连检测 |
| Python 心跳机制 | [app/api/v1/chat.py](../lingXi-agent/app/api/v1/chat.py) `_with_heartbeats()` | 异步心跳 + 超时 + 断连取消 |

<a id="chat-arch-boundary"></a>

### 1.7 关键架构边界

```
┌──────────────────────────────┐       HTTP/SSE       ┌──────────────────────────────┐
│     Java (lingXi-manage)     │ ◄─────────────────── │     Python (lingXi-agent)    │
├──────────────────────────────┤                      ├──────────────────────────────┤
│ • 用户身份鉴权 (Spring Security) │                      │ • LLM 模调用 (LangChain)     │
│ • 会话归属校验 (requireOwnedSession) │                      │ • Prompt 动态构建 (@dynamic_prompt) │
│ • 对话历史持久化 (MySQL)      │                      │ • 工具执行 (Tavily 搜索)      │
│ • 看板数据加载 (DashBoard)    │                      │ • 结构化输出解析 (Pydantic)    │
│ • 会话 CRUD                  │                      │ • 短期记忆管理 (PostgreSQL)    │
│ • SSE 事件转发               │                      │ • SSE 事件生成                │
│ • 共享密钥认证                │ ── X-Agent-Service-Key ── │ • 密钥校验 (constant-time)    │
└──────────────────────────────┘                      └──────────────────────────────┘
```

#### 身份隔离原则

- **用户身份** 放在 `AgentContext.user_id` 中，每次请求由 Java 传递
- **会话身份** 放在 `thread_id` 中，由 Python 使用 SHA-256 哈希生成非 PII 命名空间
- 两者不得混用，`thread_id` 可由前端显式指定或自动生成

### 2.1 整体触发流程

小说章节分析是灵犀 AI 视频生成管线的核心环节，负责将章节原文转换为下游图片、视频和配音智能体可消费的**结构化故事圣经（Story Bible）**。

#### 触发入口

```
前端/定时任务
  → AiVideoChapterAnalysisWorker.analyze(taskId, chapterId)
```

#### 整体流程图

```
AiVideoChapterAnalysisWorker.analyze(taskId, chapterId)
  │
  ├─ 1. claimStoryBibleTaskWithLockRetry(taskId)
  │     └─ 悲观锁原子领取任务（防重复执行，最多重试 3 次）
  │
  ├─ 2. 数据准备
  │     ├─ chapterMapper.selectAiVideoChapterByChapterId()    加载章节原文
  │     ├─ characterMapper.selectAiVideoCharactersByProjectId() 加载项目人物
  │     └─ modelConfigService.getRequiredConfig()             获取 LLM 运行时配置
  │
  ├─ 3. 调用 Python Agent
  │     └─ ChapterAnalysisClient.analyzeChapter()
  │           └─ HTTP POST (NDJSON 流式) → Python /api/v1/video/analyze-chapter/stream
  │
  ├─ 4. 接收进度事件
  │     └─ progressListener → updateStoryBibleProgress() 实时回写进度到 DB
  │
  ├─ 5. 接收最终结果
  │     └─ AnalysisResult (story_bible JSON)
  │
  └─ 6. persistResult() 持久化到 DB
        └─ persistResultInTransaction() 事务内执行:
              ├─ AiVideoStoryBible     故事圣经
              ├─ AiVideoCharacter      人物
              ├─ AiVideoScene          场景
              ├─ AiVideoShot           镜头
              ├─ AiVideoAsset          素材草稿（图片/视频）
              ├─ AiVideoAssetRelation  资产引用关系
              ├─ 更新章节状态 → ANALYSIS_COMPLETE
              └─ 更新任务状态 → COMPLETED
```

### 2.2 Java 侧详细流程

#### 2.2.1 任务领取

```java
// AiVideoChapterAnalysisWorker.java
public void analyze(Long taskId, Long chapterId) {
    // 悲观锁领取，防止多 worker 重复执行
    if (!claimStoryBibleTaskWithLockRetry(taskId)) {
        return; // 已被领取或不再排队
    }
    // ...
}

private boolean claimStoryBibleTaskWithLockRetry(Long taskId) {
    for (int attempt = 1; attempt <= 3; attempt++) {
        try {
            return taskMapper.claimStoryBibleTask(taskId) == 1;
        } catch (PessimisticLockingFailureException ex) {
            waitBeforeTaskStatusRetry(taskId, "CLAIM", attempt, ex);
        }
    }
    return false;
}
```

#### 2.2.2 数据准备

```java
// 加载章节数据

// 加载项目人物（跨章节复用）

    .selectAiVideoCharactersByProjectId(chapter.getProjectId());

// 构建项目人物 JSON 数组

    node.put("visualPromptBase", character.getVisualPromptBase());
    node.set("aliases", objectMapper.readTree(character.getAliasesJson()));
    projectCharacterNodes.add(node);
}

// 获取 LLM 运行时配置
AiVideoModelConfig runtimeConfig = modelConfigService.getRequiredConfig();
```

```python
async def analyze_chapter_stream(request: AnalyzeChapterRequest):
    """流式章节分析端点，返回 NDJSON 进度事件 + 最终结果"""
    async def event_stream():
        queue = asyncio.Queue(maxsize=16)
        # 进度回调 → 放入队列
        async def report(stage, progress, message):
            await queue.put({"type": "progress", "stage": stage, ...})
        # 执行分析
        async def run_analysis():
            result = await _run_chapter_analysis(request, ...)
            await queue.put({"type": "result", "response": result.model_dump()})
            await queue.put(None)  # 结束信号
        # 逐行输出 NDJSON
        task = asyncio.create_task(run_analysis())
        while True:
            event = await queue.get()
            if event is None: break
            yield json.dumps(event) + "\n"
```

```python
# 每句对白必须在镜头时长内自然说完
```

#### Java 侧异常处理

```
Python 返回失败
  → result.isSuccess() == false
    → updateTaskStatusWithLockRetry(taskId, "FAILED", 100, errorCode, errorMessage)
    → chapterMapper.updateAiVideoChapterAnalysisStatus(chapterId, "FAILED", "FAILED", null, 0)

Java 捕获异常
  → log.error("AI视频章节解析失败...")
  → updateTaskStatusWithLockRetry(taskId, "FAILED", 100, "CHAPTER_ANALYSIS_FAILED", message)
  → chapterMapper.updateAiVideoChapterAnalysisStatus(chapterId, "FAILED", "FAILED", null, 0)

暂停检测
  → isStoryBibleTaskPaused(taskId) == true
    → 忽略结果，停止保存和状态回写
    → 抛出 AnalysisPausedException
```

#### 修复机制

```
阶段一修复（骨架）:
  PLAN_REPAIR_PROMPT → 最多 1 次修复
  输入: 原始 Prompt + 校验错误 + 无效骨架
  输出: 修正后的完整骨架 JSON

阶段二修复（场景）:
  SCENE_REPAIR_PROMPT → 每场景最多 2 次修复
  输入: 场景 Prompt + 校验错误 + 无效场景
  输出: 修正后的完整场景 JSON

阶段三修复（最终）:
  REPAIR_PROMPT → 最多 2 次完整修复
  或场景级局部修复（对白时长问题）
  输入: 原始 Prompt + 校验错误 + 无效响应
  输出: 修正后的完整故事圣经 JSON

总修复次数 = 骨架修复 + 场景修复 + 最终修复
```
