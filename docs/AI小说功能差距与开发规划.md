# AI 小说写作功能差距分析与开发规划

> 版本：v1.0
> 日期：2026-08-10
> 对标：waqupin.com 功能页（蛙趣拼文，长篇网文 AI 写作工具）
> 适用工程：`lingXi-agent`（Python Agent）、`dkd-parent`（Java 后端）、`lingXi-vue`（前端）

## 1. 现状结论

灵犀项目当前已完整实现：AI 流式创作对话（续写/扩写/润色指令）、梗概拟写、作品/章节/设定卡管理、AI 续写下一章、章节分析（骨架规划→场景/分镜生成→修复校验）、故事圣经（世界观/时间线/关系/不可变事实）、人物跨章节复用、素材资产库（三视图/场景图/关键帧/视频 + 版本审批血缘）、图片与视频生成、异步任务系统。

其中 **AI 视频管线（章节 → 分镜 → 资产生成 → 视频）是相对 waqupin 的差异化优势**，waqupin 仅有短剧剧本与分镜能力。

差距集中在纯文本创作侧：伏笔、大纲、精修、风格、素材库、构思 Agent 等。

## 2. 差距清单

### 2.1 完全缺失

| 功能 | 说明 |
| --- | --- |
| 小说构思 Agent | 无"模糊创意 → 追问补全 → 构思文档"能力，仅支持手动填设定卡 |
| 千章三层大纲 | 设定卡 outline 类型为手动维护，无独立大纲生成/存储/审核接口 |
| 拆书素材库 | 无任何代码（素材提取/语义检索/素材包导入导出/本地向量化） |
| 短剧剧本/分镜/导出 | 代码库中"短剧"零命中 |
| 精修模板系统 | 润色仅为 `ChatComposer.vue` 快捷指令，无模板管线、修改点标注、统计 |
| 伏笔管理系统 | 仅在 `novel_prompts.py` 会话摘要中保留"未解决伏笔"字段，无数据表、状态、回收时间、等级 |
| 风格实验室 | `NovelSettingItem` schema 支持 style 类型但前端未暴露，无模板沉淀/预览/去 AI 味 |

### 2.2 部分实现，深度不够

| 功能 | 现状 |
| --- | --- |
| 节奏控制 | 无法选节奏档位，无节奏评分/调整建议（对标 Pacing Levels） |
| 角色卡片 | 有设定卡 character 类型，但无 MBTI/关系网/成长轨迹/章节前后对比 |
| 世界观迭代 | 设定卡手动维护、静态注入；对标"跟随剧情 Agent 自动升级" |
| 长篇分层记忆 | 会话级摘要记忆，无"全局/项目/章节"三层持久记忆 |
| API 测试工具 | 有模型配置管理，无"测试 API 连接"能力 |

## 3. 开发规划（按建议顺序）

| #  | 功能 | 当前状态 | 实现价值 | 预估工作量 | 涉及模块 |
|----| --- | --- | --- | --- | --- |
| √  | 伏笔管理系统 | 仅提示词字段（`novel_prompts.py` 摘要保留） | 网文刚需、卖点强；状态追踪（已埋/待解/已解）+ 回收时间 + 等级，创作时注入上下文 | 中（3-4 天）：1 张表 + Java CRUD + 提示词注入 + 前端面板 | `AiNovelSetting` 扩展 / `novel_prompts.py` / `SettingNotebook.vue` |
| √  | 大纲生成与存储 | 仅手动设定卡 + 对话指令 | 千章写作的前提；三层大纲（全书→卷→章）+ 断链修复，替换现有手写 outline | 中（4-5 天）：Agent 链 + 大纲表 + 前端编辑树 | `novel.py` / 新 chain / `ChapterTree.vue` |
| 3  | 精修模板系统 | 仅"润色这段文字"对话指令 | 复用现有流式链路，改造成本低；22 场景模板 + 修改点标注，直接可复制的卖点 | 小（2-3 天）：提示词模板库 + 前端指令面板 | `novel_prompts.py` / `ChatComposer.vue` |
| 4  | 风格实验室 | schema 支持但前端未暴露（style 类型） | 模板沉淀 + 预览 + 去 AI 味；补上前端暴露即可用 | 小（1-2 天）：前端暴露 style 类型 + 模板管理 | `SettingNotebook.vue` / `AiNovelSetting.java` |
| 5  | 节奏控制系统 | 无 | 5 档节奏参数 + 章节节奏评分/建议，与精修模板联动；差异化加分项 | 中（3-4 天）：参数进上下文 + 评分提示词 + 结果展示 | `request.py` / 新分析链 |
| 6  | 拆书素材库 | 无 | 素材积累是长线价值；语义检索 + 素材包导入导出 + 向量化（可用 PostgreSQL pgvector） | 大（7-10 天）：导入解析 + 向量检索 + 素材表 + 前端库 | 新模块 / `knowledge` 复用 |
| 7  | 小说构思 Agent | 无 | 入门体验好；对话式追问补全构思文档，可复用现有 web_search + Agent 框架 | 中（3-4 天）：新 Agent + 构思文档结构化输出 | `novel_builder.py` 扩展 |
| 8  | 分层持久记忆 | 会话级摘要记忆 | 全局/项目/章节三层记忆，跨会话保一致性；有 PostgreSQL checkpoint 基础 | 大（5-7 天）：记忆表 + 检索注入逻辑 | `checkpoints.py` / 新 service |
| 9  | 角色卡片增强 | 设定卡 character 类型 | MBTI/关系网/成长轨迹 + 章节前后对比；提升人物一致性 | 中（4-5 天）：schema 扩展 + 对比分析提示词 | `request.py` / 设定卡前端 |
| 10 | 短剧剧本/分镜/导出 | 无 | 已有视频管线，短剧可复用场景/分镜/生图提示词，导出 MD/JSON/CSV 成本低 | 中（4-5 天）：短剧形态参数 + 导出工具 | 复用 `chapter_analysis` 链 |

## 4. 建议

先做 **1 → 2 → 3**（纯文本侧、成本低、卖点最直观），第 4 项可顺手带出；5-10 按需排期。短剧与视频管线已有优势，不建议模仿 waqupin 的短剧形态，优先巩固现有 AI 视频管线差异点。
