# 总初始化 SQL 与数据库结构核对

核对日期：2026-11-07。唯一初始化入口：[`dkd-parent/sql/lingxi_all.sql`](../dkd-parent/sql/lingxi_all.sql)。

## 核对方式与结果

使用本机已有 MySQL JDBC 驱动，通过本地环境变量及忽略的配置文件连接当前数据库。连接设为只读，只调用表元数据与 `SHOW CREATE TABLE`，不读取业务数据、种子数据或安全配置值，不执行 DDL/DML。

将总脚本的 CREATE TABLE 与后续 ADD/MODIFY COLUMN、ADD KEY 合并后，对照实际结构；归一化标识符大小写、整数显示宽度、数字默认值、主键隐含 NOT NULL、内联唯一约束和 InnoDB 自动创建的外键支撑索引。

| 核对项 | 数量 | 结果 |

| 表名 | 80 | 一致 |
| 字段名、类型、unsigned、可空、自增、默认值 | 946 | 一致 |

核对涵盖小说计划章节号、节奏档位、章节软删除、资料同步任务、对话正文及快照 MEDIUMTEXT、视频任务恢复计数，以及旧表在总脚本后段追加的字段/索引。

没有把当前数据库的业务行导出到仓库。原始结构与比对中间文件仅放在忽略的 `tmp/sql-audit/`，不属于部署依赖。

## 整理结果

- 原有 9 个 `migration_*.sql` 的新环境结构要求已包含在总脚本中，移除重复文件；历史内容可在 Git 历史查阅。
- 历史迁移中的旧记录回填、异常运行任务修复与角色授权搬迁属于存量库升级处理；新库不存在这些历史状态，不把它们重复追加到初始化 SQL。
- 总脚本继续保留种子数据与菜单/角色权限初始化。成功提示移到全部表结构、菜单权限和安全配置处理完成之后。
- 菜单修正：灵犀智能助手为独立一级菜单 `/ai`；AI视频创作为一级目录 `/aiVedio`，包含项目、生成队列与小说写作台。灵犀业务仅承载零售业务页面，业务 CRUD 按钮按 `manage:%` 权限生成，不再给 AI 对话生成无效按钮。菜单 ID 先插入再生成自增按钮，避免 ID 冲突。
- `python tests/sql_init.test.py` 会在 SQLite 内存库执行总脚本中的菜单种子语句（适配 MySQL 变量与 UPSERT），检查 AI 页面祖先、入口权限和菜单 ID 冲突；该检查不会修改实际数据库。现有数据库菜单未随本次文件修改自动调整。

## 使用边界

本次是只读结构核对，未在空 MySQL 实例上重新导入验证，也未比较业务行、菜单授权的实际数据、字符集/排序规则、表注释或索引名称。Quartz 表名在 Windows 数据库中显示为小写，脚本使用大写，按 MySQL 在该环境的大小写规则归一化；跨平台部署需确认 `lower_case_table_names` 与 Quartz 配置一致。

总脚本包含 DROP TABLE，仅供新环境使用。已有业务库必须先备份并对照本次差异单独编写升级 SQL，不能因为 CREATE TABLE IF NOT EXISTS 而认为整份脚本可安全重跑。
