# 知识引用证据快照设计决策

- 日期：2026-11-06
- 状态：已实现

## 背景

内部知识检索已经过滤角色、有效期与版本，但回答中的引用仅展示标题，且刷新后丢失。
用户无法查看这次回答参考的片段，也难以区分旧版本资料和最新规范。

## 决策

复用现有 citation SSE 与 ui_json 历史字段，增加有界证据快照。
片段来自检索工具实际提供给模型的文本，最多 2000 个 Unicode 字符；每个回答最多 20 个来源。
Python 与 Java 只转发白名单字段，前端使用原生详情展开元素和文本插值显示片段。
成功回答将引用与 OpenUI 渲染共存保存，旧历史兼容，不新增依赖、配置项、表或字段。
已有 `ui_json` 和正文 `content` 从 `TEXT` 扩大为 `MEDIUMTEXT`：20 条中文证据、
合法的 32,000 字符中文输入或长回答都可能超过 64 KiB，
需在发布前执行独立迁移 `dkd-parent/sql/migration_ai_model_history_ui_json_capacity.sql`。
展示快照超过 MEDIUMTEXT 的 UTF-8 字节上限时丢弃该快照，仍保存正文，避免展示数据阻塞对话持久化。
审批恢复时从该用户该会话的当前轮工具记录重放引用，以便最终回答保留暂停前的证据。

## 影响与边界

这是回答生成时的检索快照；更新索引或修改角色不会追溯删除已经交付并保存在聊天历史中的文本。
不提供实时文档浏览，不暴露内部存储地址，不根据来源标识访问额外文件。
客户端历史写入不能伪造生成元数据。失败或取消的回答不保存成功快照。
未启用内部知识检索时，保持现有聊天行为。既有部署先执行上述扩容迁移，再按 Agent → Java → 前端顺序更新。

离线测试覆盖权限筛选、模型证据一致性、Unicode 截断、字段白名单、去重与总量限制、
审批恢复、成功持久化、失败不落库、客户端伪造阻断、存储容量、OpenUI 共存及旧历史恢复。
