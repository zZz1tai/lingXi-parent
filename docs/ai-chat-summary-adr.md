# AI 对话纪要设计决策

- 日期：2026-11-06
- 状态：已实现

## 背景

对话、业务查询和知识检索已有持久化历史，但用户缺少把讨论整理成可保存行动清单的入口。

## 决策

在现有 AI 对话页增加“对话纪要”，复用 Element Plus 和既有模型配置。
Java 校验登录用户与会话归属，读取有效历史并限制条数和总字数；Python 使用独立 LCEL 链
生成严格结构化结果。前端显示摘要、结论、待办、待确认事项，并复制或下载 Markdown。
结果只在当前弹窗中保留，关闭、切换会话或历史改变即失效。

不用普通聊天请求生成纪要，避免总结指令进入原会话或触发业务工具；不新增表、依赖或配置项。
待办仅作文本提炼，未知负责人和期限保持未明确，用户自行核对和执行。

## 影响与验证

长会话只使用最近 100 条、最多 48,000 字符，截断时明确标识，无法代替完整历史归档。
既有部署按 Agent → Java → 前端顺序发布，无数据库迁移。
离线测试覆盖归属权限、无效状态筛选、输入长度、Unicode 截断、模型输出校验、认证、
出站白名单、HTTP 契约、Markdown 安全及前端异步响应隔离。
真实模型输出质量和完整浏览器交互需在已配置运行环境中验收。
